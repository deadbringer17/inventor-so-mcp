# Inventor SO MCP — development status

Target: Inventor 2027 x64. Full functional scope remains the 80-point assessment in `analisi-spec-inventor-so-mcp.md`; the work below does not replace it with a smaller goal.

## Architecture decision

The production implementation lives in `bridge/`: an Apache-2.0 subtree imported from bimwright/ipt-mcp at d539a2ee7295747c7ef3b44a64aa870e8889deac. Its license and attribution are preserved. Root `src/` remains the MIT NeonGlay baseline/reference, not the production entry point. No hsavas code is incorporated.

Server runs separately from Inventor, using the MCP C# SDK and an authenticated local pipe to an STA-dispatched add-in. Inventor 2027 add-in targets .NET 10; server currently targets .NET 8 independently. Interop must come from the local Autodesk installation and is not redistributed.

## Atomic batch implementation — 2026-09-12

- Added `inventor_atomic_batch`: 1–32 allowlisted part-modeling operations in one owned Inventor transaction. Requires active document ID and event revision; rejects stale plans and an already active transaction. Scripting, exports, file IO, document lifecycle and nested batches are excluded.
- Rebuild and non-suppressed feature health are checked before commit. Errors and observed deadline expiration trigger rollback. Preview executes real changes and then aborts: it requires write permission and is not a read-only simulation. Intermediate results may describe temporary entities that no longer exist after rollback.
- User interaction is temporarily disabled and its previous setting restored. Transaction ownership is checked before ending or aborting; rollback failure is explicitly reported. This is not protection against every external COM client or all concurrent modifications.

## Assemblies constrainable without a user selection — 2026-09-13

- `list_topology` now covers assemblies: `kind='occurrence'` lists direct components with position, grounded state and constraint count; `kind='face'` and `'edge'` return assembly-context proxies, scoped to one component with `component_id` or across all of them. Proxies are built with `CreateGeometryProxy`, the same idiom the assembly reference resolver uses, and carry the portable `face_proxy` ids that `create_constraint_safe` already required.
- This closes the last gap that forced a human into the loop: constraint faces could previously come only from `inventor_get_selection`, so an unattended caller could position components but never constrain them. An assembly can now be built and constrained end to end from a description.
- Planar faces report `outward_normal` and `param_reversed` next to the raw surface `normal`. ## Assembly constraint types completed — 2026-09-13

- `create_constraint_safe` now covers mate and flush (planar), `mate_axis` (cylindrical or conical faces), `insert` (two circular edges), `angle` (degrees) and `tangent` (inside or outside), replacing the planar-only surface. All of them keep the existing guarantees: owned transaction, preview by default, rebuild plus constraint-health check, and interference and minimum-clearance validation across every unsuppressed top-level pair, with rollback on failure.
- The geometry kind is verified against the requested type rather than inferred. Inventor infers an axis from a plane and a plane from a cylinder, which silently produces a constraint the caller did not ask for; a mismatch now fails with MATE_NEEDS_PLANAR_FACE, MATE_AXIS_NEEDS_CYLINDER or INSERT_NEEDS_CIRCULAR_EDGE. `EntityReferences` gained resolvers for any assembly face proxy and for edge proxies.
- `ConstraintCreateRequest` validates per type: angle takes `angle_degrees` and refuses an offset, every other type takes `offset_mm` and refuses an angle, `axes_opposed` defaults to true for insert and `inside` to false for tangent. Ids may be given as `entity_a_id`/`entity_b_id` as well as the original `face_a_id`/`face_b_id`. Unit suite: 489 passing.

## Joints, grounding and cross-document work — 2026-09-13

- `create_joint_safe` builds rigid, rotational, slide, cylindrical, planar and ball joints between two component origins, with optional gap and the two flip flags. A joint states the degrees of freedom that remain instead of the several constraints that would add up to the same thing. Validation matches the constraint path — owned transaction, rebuild, health of every constraint AND joint, interference and clearance over all pairs — and the result carries `motion_path_validated: false`, because a joint deliberately leaves motion available and only the assembled position was checked.
- Joint origins must be circular edges: Inventor refuses a cylindrical face with a bare E_FAIL, verified by probing both. The handler now answers JOINT_ORIGIN_REJECTED naming the geometry to use.
- `create_constraint_safe` gained `symmetry` (mirroring about a third planar reference) and `transitional` (a face kept in contact along another). Neither carries a measurement, so passing an offset or an angle is refused rather than ignored.
- `ground_component_safe` grounds or ungrounds one direct occurrence. A request that matches the current state reports `unchanged` instead of opening a transaction. Grounding moves nothing, so no clearance claim is made — only rebuild and constraint/joint health.
- `activate_document_safe` brings an open workspace document to the front, and `list_parameters` accepts a `document_id` to read any open part without activating it. Together these make cross-part work reachable: read a dimension from one part, activate the other, write it in. Inventor has no cross-document parameter link outside iLogic or a derived part, so propagation is performed by the caller and is not claimed to be a live link.
- Adaptive occurrences remain deliberately excluded everywhere: an adaptive part changes its own geometry when the assembly solves, which is the opposite of the explicit, verifiable edits this surface offers. The guards reject adaptive occurrences rather than silently working on them.
- Unit/protocol suite: 495 passing. Live MCP verification on Inventor 2027 (`scripts/smoke-assembly-autonomous-mcp.py`, package 20260913-151110-9748b025) in one run: mate, insert centring a pin at x=12.0/y=0.0, angle preview, grounding plus an `unchanged` repeat, an invalid joint type refused, a cylindrical face refused as a joint origin, a rotational joint committed and recorded, symmetry without its plane refused, parameters read from a non-active part, and a value carried into another part after activating it. Workspace, sheet-metal shop, assembly and atomic smokes all still pass.
